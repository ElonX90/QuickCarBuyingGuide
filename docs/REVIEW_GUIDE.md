# 维护者证据审核与发布流程

投稿入口：[证据表单](https://github.com/ElonX90/QuickCarBuyingGuide/issues/new?template=evidence.yml)。任何有 GitHub 账号的人可提交 Issue 或 Fork 后开 PR；普通投稿者不能直接改 main。

## 审核状态

| 状态 | 含义 | 是否参与正式计分 |
|---|---|---|
| pending | 尚未完成原文、范围或冲突核验 | 否 |
| accepted | 接受来源中的指定有限事实，保留审阅记录 | 是，但只对对应观察和范围 |
| rejected | 原文不支持、范围错误或证据不可核实；记录原因 | 否 |
| conflicting | 有实质冲突尚未解决 | 否；当前项目保持未知或撤下有冲突的旧引用 |

## 维护者必须检查

- 打开原文，确认发布者、正文日期、页码/段落/时间点以及完整上下文。网址存在不等于该观点成立。
- 对齐车型世代/动力、企业法人、地区、报告期、单位和事件起止点。销量车系可能覆盖多个版本，不能把某个版本的证据外推到全部销量。
- 开发周期区分整车与平台、立项与草图、SOP 与上市/交付；两个日期缺一时不伪造月份。
- 社保和外包确认真实用工主体、岗位/员工范围、报告期、证据覆盖面和整改情况。招聘广告只有在真实且明确时支持所列岗位的线索，不自动支持品牌全范围结论。
- 与现有资料及可获取的独立来源交叉核验。重大负面或争议事实尽量增加独立复核；无法澄清时保持未知。
- 将接受的有限事实与不能证明的事项分开写，登记审阅状态、人、日期、原因；在 PR 引用 Issue 和原文定位。
- 运行校验并复算，审阅分数区间及购前条件的变化，合并后检查 CI；纠错保留 Git 历史。

## 软件检查的边界

程序检查来源引用、审阅状态、主体/范围字段、权重、未知传播、销量前100完整性和生成结果的一致性；不能判断文件真假、宣传是否兑现或审阅人是否冒名。贡献者自行填 accepted 不算维护者批准。维护者应在真实 PR review 中完成实质复核。

.github/CODEOWNERS 已指定 @ElonX90。该文件用于请求审核，并不等于已经开启 GitHub 分支保护。建议仓库所有者在 GitHub Rules / Branch protection 对 main 要求 PR、Code Owner review 和 validate 状态检查，禁止自动合并未审来源；这项仓库设置须由所有者确认生效。

首版来源的审阅人为 Codex initial research，表明原有公开研究，不冒充人类维护者已经签字。社区补证可要求更严格原始资料；收集更多资料会改善完整性，但本指数没有经真实安全结果训练。
